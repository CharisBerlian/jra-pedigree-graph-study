# Original experiment: input contract and execution map

This documents the historical implementation and required inputs. It is not a complete or independently runnable source-data release. The data custodian must supply authorized exact inputs, artifacts and rights; no public contact or access entitlement is asserted. Collection and repair from original web pages are not reconstructed end to end by this packet. Run the stage examples from the `reproduction/` directory, replacing every uppercase placeholder with an authorized path or value. They are a stage map, not an invitation to run costly fitting or to overwrite frozen outputs.

## Input contracts

`input_schemas.json` records schema-only SQLite snapshots and CSV headers observed in the original inputs; it contains no data rows. It lists all columns and SQLite types, not just model predictors. `feature_allowlists.json` and `SUPPLEMENT_S1.md` specify the ordered model predictors and categorical types. Key fields are:

- Repaired race database: `races_r` contains `race_id`, `race_date` (YYYYMMDD text), race type, surface, venue, distance, going and class; `runners_r` contains the three-part key `(race_id, horse_id_netkeiba, horse_number)`, official finish/status, entrant fields and retrospective odds/popularity. See the full column schema in `input_schemas.json`. Label and outcome fields are not test predictors. The source and repair provenance are required separately; a fresh scrape is not an exact substitute.
- Pedigree source and patch databases each contain `pedigree_edges(child_jbis_id, parent_jbis_id, relation, generation)`; `relation` must be `sire` or `dam`, each child/role must resolve consistently, and the source script rejects missing ancestors and cycles. Despite legacy column names, these are Netkeiba IDs. Exact source snapshots, collection dates, permission and history are not distributed or fully reconstructible here.
- Derived features database: `entries` has the three-part key, split, label, surface, context, history count and presence flags; `history_long` uses the three-part key plus `hist_rank` and holds prior-race fields; `meta` records policy and exclusions. The builder validates status/position consistency, joins and strictly earlier history. Market values are rejoined from the repaired race database, not stored in `features.db`.
- Graph bundle: private `training_horses.txt` has one sorted unique nonempty root ID per line; private `pedigree_edges.csv` has exact header `child,parent,relation`; the directory also needs `manifest.json`, `graph_pilot.py` and `requirements-graph.txt`. The exact historical manifest is supplied as `graph_input_manifest.json`; an authorized custodian must restore it as `manifest.json` with the original matching payloads, whose lengths and hashes it records. It specifies the 2010--2021 eligible training roots and 93,474 nodes / 173,412 edges, not test roots or outcomes. The graph loader verifies the manifest purpose, checksums, closure, roles, cycles and counts. The private root/edge files are not in this packet.
- Train/validation exports: the three seed-specific CSV/GZip files use the 121-column `train_validation_export` schema in `input_schemas.json`, including `label`; the `label` column is a target, never a predictor. Exact per-setting allowlists select the predictors. Each seed file requires a `Path(input).with_suffix('.json')` sidecar with `splits` exactly `["train", "validation"]`, matching `seed` and verified `data_sha256` (or the documented older gzip/payload-hash combination). Each must contain complete races and must not contain test rows.
- Test exports: `test_seed0/1/2.csv[.gz]` use the 120-column `test_export` schema, with no target label or result fields, plus exactly one corresponding sidecar per file. The sidecar declares `splits: ["test"]`, the correct `seed`, `test_labels_read: false` and `test_metrics_computed: false`, and binds input/graph hashes. All seeds must have the same keys, complete race rosters and consistent coverage. Historical metadata can contain absolute local paths: treat regenerated sidecars as private until reviewed.
- Prediction output: 180 CSV/GZip files are organized `family/surface/setting/seedN/test_predictions.csv.gz`, with the six-column `prediction_output` header in `input_schemas.json`; `prediction` is a finite probability and `selected_top3` identifies the three deterministic race selections. `tables/prediction_inventory.csv` records the historical relative paths, sizes and hashes, not rows. For scoring, the matching feature database, source database, test inputs, frozen manifest, spec, inference report and validation thresholds are required.

The exact historical `experiment_spec_2026-09-13.json` is included. Its source-byte SHA-256 is `1993d22e1f1561dd052e33c72835bf58cfa9f9f9ee9ab9cc8094e3dd3d299f31`; the sorted, indented runtime serialization checked by inference hashes to `942a9dbe1138977c74e501aee43832756510f492586832099b4272e9bcd64b4c`. The unchanged selection manifest hashes to `41d116385d2b6b08e4974a05f026ee58cf3d65ad48d5b30622d11332c749e371`. The spec's closed-test flags describe the historical lock at creation, not the present state of this already examined test set. Python and exact package pins are recorded inside `runtime`; `requirements-graph.txt` gives graph-specific pins. The prediction evaluator also needs NumPy/scikit-learn.

## Stage map after authorized input acquisition

1. `python code/build_features.py --source REPAIRED_DB --output-dir NEW_DIR` builds `features.db`, `split_manifest.csv` and `exclusions.csv` after checks. Its output is staging/published only after checks; use a fresh directory. `code/graph_pilot.py` exposes the training-root and pedigree loading/build functions, while `graph_production.py` verifies the original immutable graph-bundle input. The original graph-bundle export was prepared separately; its raw roots and edges, exact manifest and acquisition/repair workflow remain custodian prerequisites, not recreated automatically by these commands.
2. On the historical Kaggle execution environment, `python code/graph_production.py --input-dir GRAPH_BUNDLE --output-dir GRAPH0 --seed 0` performs the seed-0 cluster search. Seeds 1 and 2 use their own fresh output directories and `--seed 1 --clusters 64` / `--seed 2 --clusters 64`. Production reports, `training_graph.edg`, `nodevectors_seedN.npz` and `cluster_centers_seedN.npy` are required downstream. Four-worker skip-gram is not bitwise deterministic.
3. `python code/prepare_prediction_seeds.py --features-db FEATURES_DB --source-db REPAIRED_DB --pedigree PEDIGREE_DB --pedigree PATCH_DB --graph-dir 0=GRAPH0 --graph-dir 1=GRAPH1 --graph-dir 2=GRAPH2 --output-dir EXPORTS` prepares three train/validation seed files and sidecars. Use actual authorized paths; duplicate `--pedigree` only when both sources are needed. The exact original data and graph are required to compare with the historical files.
4. For each of three families, two surfaces and ten settings, run `python code/run_experiments.py --family FAMILY --surface SURFACE --setting SETTING --stage tune --seed 0 --input EXPORT_SEED0 --spec experiment_spec_2026-09-13.json --output MODEL_ROOT --mode scientific`. Each tune run executes four candidates. Then use `--stage refit --seed N --input EXPORT_SEEDN` for N=0,1,2, same family/surface/setting, spec and root. This is 60 tuning runs / 240 candidate fits and 180 refits, not one command. The code enforces Kaggle and exact spec runtime pins; it does not merge training and validation.
5. Run `python code/audit_experiment_outputs.py --root MODEL_ROOT --spec experiment_spec_2026-09-13.json --mode scientific --stages all`, then `python code/build_experiment_selection_manifest.py --root MODEL_ROOT --spec experiment_spec_2026-09-13.json --output NEW_MANIFEST`. The manifest builder refuses overwrite. A fresh run has new artifacts and is not the historical manifest or an untouched confirmatory replication. For re-evaluating the historical frozen models, use the included historical manifest and the exact original output tree, with hash-bound models, preprocessing, thresholds, selection/configuration and completion markers. `run_test_inference.py` verifies the manifest-bound source files (`audit_experiment_outputs.py`, `evaluate_locked.py`, `run_experiments.py`, `experiment_features.py`) in its own code directory.
6. `code/prepare_test_prediction.py` requires `--features-db`, `--source-db`, repeated `--pedigree` and all three `--graph-dir SEED=PATH` options, plus `--output-dir`; it exports test features without labels. `python code/run_test_inference.py --manifest MANIFEST --spec SPEC --model-root MODEL_ROOT --test-input TEST_INPUT_DIR --output NEW_INFERENCE_DIR` performs locked inference (Kaggle guard), writing 180 predictions and an inference report without test metrics. Never substitute a new model tree under the old manifest.
7. `python code/evaluate_locked_test_results.py --manifest MANIFEST --spec SPEC --inference-report INFERENCE_REPORT --predictions-root PREDICTIONS_DIR --features-db FEATURES_DB --source-db REPAIRED_DB --test-input-dir TEST_INPUT_DIR --output-dir NEW_EVALUATION_DIR --bootstrap-replicates 2000` joins keyed labels only for post-inference evaluation. The declared whole-race seed is 20260913 and paired differences reuse draws; output includes historical 36 contrasts per primary metric. Run corrected aggregate table/plot generators separately as in `README.md`.

All stages require the exact original schema and provenance or an explicitly new, documented experiment; none supplies missing private data or guarantees identical fits. A clean-room run of supplied aggregate reporting is the only full run verified with this release alone.
