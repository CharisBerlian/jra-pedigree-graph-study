# Focused ancestor-consistency and parent-control protocol — implementation approved; pre-fit review pending

This fixed proposal is post hoc: the existing 2024–2025 test has been inspected previously. It is not registered prospectively and no new test feature, prediction, outcome or metric may be accessed until root reviews the actual complete model and selection freeze. No performance-dependent variant selection is allowed. Root approved the four-arm design for implementation after independent review; root review of the completed actual pre-fit manifest remains required before any scientific model job.

## 1. Cohorts and predictors

Use the original eligible flat-race entries and full race rosters: training 2010–2021 (548,756 entries in 38,447 races; 271,549 turf, 277,207 dirt), validation 2022–2023 (88,106 entries, 6,401 races; 42,783 turf, 45,323 dirt), and exploratory test 2024–2025 (89,137 entries, 6,465 races; 43,477 turf, 45,660 dirt). Surface-specific classifiers and the original strict-before-target-date recent-history policy remain unchanged. Before model fitting, freeze the **training/validation** race and entry keys, rows, histories, non-graph values and labels; preserve all starters in a race. The test data are accessed only after the separate model-freeze review. Review any mismatch instead of dropping entries. Final-field, going, body-weight, historical completeness and retrospective pedigree availability remain assumptions, not demonstrated real-time access.

The arms have these exact logical schemas:

* **H:** original S2 context and history, 43 predictors.
* **Gmixed:** original S6, 43 H plus 64 coordinates and five graph descriptors (112 predictors); use the existing direct-else-first-available-generation rule.
* **Gancestor:** the same 112 predictor names and frozen graph/centroid space, but apply the first-available-generation unique-ancestor rule to every row and never use that row's own vector directly. Recompute all 64 coordinates, representation status, depth, ancestor count, missing indicator and nearest-centroid category from this vector. Never replace the original historical artifact.
* **P:** H plus nine numeric features: for each of sire, dam and damsire, an identifier-available indicator, count of eligible prior same-surface starts, and shrunk prior top-three rate. Total 52 predictors; no raw identity category or outcome of the target row is a predictor. P is a deliberately simple comparator, not an estimate of genetic effects.

Any alternative arm, different dimension, external model or enlarged grid requires a reviewed versioned protocol change, not an unrecorded improvement cycle. Market models in the original paper are a separate analysis; these four arms do not establish market-controlled graph gain.

## 2. Frozen graph and ancestor rule

For seed 0, 1 or 2, use the respective original production 2010–2021 graph node vectors and k=64 centroids, with their historical report, vector, centroid and graph hashes verified. Within that seed, Gmixed and Gancestor must use exactly the same coordinate space and centroids. Never concatenate independently trained seed spaces in a single model. The graph was fitted with the original 2010–2021 starter-root union, including later training-period relationships; this is not a rolling or out-of-horse graph.

For Gancestor, inspect parent generation 1, then 2, then 3. At each depth deduplicate ancestor IDs, exclude the focal horse's ID if a malformed cycle places it in the frontier, and select the first generation containing at least one node with a vector. Average those available 64-dimensional vectors with equal weight using deterministic ID order. Record status `fallback`, selected depth, number of unique available nodes, and missing=0. If none exists, use 64 zeros, status `missing`, depth missing, count 0, missing=1 and cluster `MISSING`. Otherwise assign the closest frozen centroid by squared Euclidean distance, breaking exact ties by lowest centroid index. The focal horse's vector is never directly substituted even if the graph contains it. This does **not** remove information contributed by the focal horse or later training roots to the original graph topology, and is not a leave-one-horse-out graph.

Apply the identical ancestry rule to train, validation and, only after the gate, test. Check one row per exact key, finite dimensions, category/missing policy, train/validation non-graph parity with H/Gmixed/P and seed-matched graph provenance. The label-free train/validation feasibility audit found all entries resolve by generation 3; actual test coverage remains unknown at this stage.

## 3. Parent-performance control, specified before new performance access

Resolve sire and dam from the same fixed pedigree relation source used by the graph; damsire is the sire of the dam. Verify exported parent IDs agree where present, and fail on conflicting relation records. An absent ID yields available=0; otherwise available=1. Group prior outcomes by **role, parent ID and target surface**. A qualifying record is an original eligible training entry of the same surface, with a valid binary top-three label, whose race date is strictly earlier than the target's race date. Count starts, not distinct horses; ties/dead heats use the original target labels. Exclude **all** prior records belonging to the focal horse from its parent summaries. This leave-focal-horse-out adjustment is possible using parent-by-horse count/success maps; it reduces direct reuse of its own recent outcomes but does not remove dependence among relatives.

For each role, let `n` and `s` be the count and top-three-positive sum after this exclusion. Use the fixed, non-data-derived prior 0.20 and pseudo-count 20: `rate = (s + 20 × 0.20) / (n + 20)`. Emit the raw count, rate and ID-available indicator. For a missing identifier, set count 0 and rate 0.20; for a known identifier with no qualifying starts, use the same count and rate but available=1. The constant prior is a predeclared regularization choice, not an empirical claim that the true rate equals 20%; it is not tuned or changed in response to validation/test results.

These P rates are explicitly supervised, prior-outcome-derived aggregate features. The inherited `external_target_encoding=false` setting describes only categorical-code preprocessing; it does not mean that P contains no target-derived aggregation. No validation or test outcomes enter the P map.

Process training dates in ascending order. For each date, compute features for every entry from the state before that date, then update the state with eligible entries from that date: no same-day outcome contributes. Freeze the complete parent and parent-by-horse maps at 2021-12-31. Use exactly those frozen training maps and fixed prior for **all** validation and later test entries; never update with 2022–2025 outcomes. Subtract each target horse's training contributions from the frozen maps before its summaries, even when it raced in training. The source population begins in 2010, so early counts are left-censored and do not measure complete lifetime parent performance. Unknown historical pedigree publication dates remain a limitation.

Before fitting, independently verify row-by-row features against a small naive reference fixture with same-day races, focal-horse exclusion, unseen/missing parent, repeated relatives, dead-heat positives and surface separation. Hash the frozen input/source data, source code, map, allowlists and final feature matrices; assert that every source outcome date is earlier than the target date for training and that no validation/test outcome enters any map. Do not open test rows to perform this check.

## 4. Fitting and evaluation

Use XGBoost, LightGBM and CatBoost on turf and dirt separately, with the same original native-category and numeric-missing policies. Fit category maps from the relevant training surface only, using the original rare threshold and missing/unknown tokens. Four original fixed candidates per arm/family/surface are trained with seed 0; select by original validation AP and the established Hit@3/round/candidate tie-break rule, with a 1,200-round cap and 75-round patience. Refit the selected parameters and rounds on the same training period only for seeds 0, 1 and 2. Use the same tested software/runtime and feature handling for every arm. A historical H or Gmixed fit may be reused only if all actual row, input, source, software, map, candidate and selection hashes match; otherwise rerun, and never compare a reduced-period model to a full-period model as an arm. No validation rows enter the final training fit.

This gives **24 arm × family × surface cells**, **96 candidate fits**, and **72 selected refits**, plus zero new graph fits and separately labeled smoke fits. If all arms are rerun, no additional market models are implied. Count and investigate capped tuning runs; the shared search budget may still be unequal in adequacy.

After validation-only fitting, verify all candidate/refit markers and hashes, predicted validation rosters, AP curves, Hit@3 tie-breakers, chosen rounds, native categorical encodings, matching train-row and software hashes, and all graph/P provenance. Freeze every model, config, seed, candidate, input, selection and evaluation source hash, all declared contrasts, and environment. Root must review this actual manifest before any new test feature access. Create all 72 label-free test prediction sets before opening test outcomes; verify keys, rosters and hashes, then join outcomes once and report all arms.

Primary contrasts are **Gancestor−H** and **Gancestor−P**, separately for all three families and both surfaces; **Gancestor−Gmixed** is secondary. Primary metric is entry-level average precision; secondary is race-mean Hit@3, computed by selecting the top three within each complete original race before subgroup membership. Average seed-specific metrics and paired differences across seeds, not scores or predictions. Within each surface use 2,000 paired whole-race bootstrap draws generated by `numpy.random.default_rng(20261029)`, the same draws for every arm/family/seed, and 2.5th and 97.5th percentile bounds. Report 72 seed-level scores, 24 arm/family/surface mean and sample seed-SD rows, and all 36 prespecified contrast/metric rows. Include race and entry denominators, ancestor availability and P zero-count rates. Intervals reflect race resampling conditional on the fitted models; multiple comparisons and repeated horses limit inference. No significance-driven seed selection, omission of negative arms, or causal claim.

For a descriptive interpretation, multiply each Hit@3 difference and each corresponding interval endpoint by 300: the result is the difference in correctly selected horses per 100 races. This is a scaling of the metric, not a profit estimate, a practical-value threshold or an equivalence claim.

## 5. Practical execution estimate and stop conditions

The existing full train/validation source is a 981,749,176-byte plain CSV on Kaggle (its local gzip is hash-pinned in `feasibility.json`). One actual private CPU stream downloaded and hashed it in 53.01 seconds; this is a single transfer observation, not a pipeline or fitting runtime. Existing original graph vectors and centroids are available locally with audited seed-specific hashes; no graph training is required. The matched feature work needs full 636,862-row train/validation roster materialization, six seed/regime graph input views and a P view, with exact storage determined after construction. Test preparation is deferred.

The matrix is 96/240 = 40% of the original candidate fits and 72/180 = 40% of its refits, but the new parent construction and full-roster graph assembly add work. A practical launch unit is one arm × family × surface cell (24 private CPU jobs), each executing four candidates and three refits; a bounded three-job active batch would require eight waves if the platform permits it. Actual concurrency/quota, per-family training time, storage, model output sizes, network behavior and total elapsed time are not established. The prior full synthetic model smoke built dependencies from source in a Python 3.13 environment, so repeated setup can be substantial; do not promise an ETA from the transfer benchmark. Freeze each job's actual input roles and source before launch, use fresh short-lived URLs, keep a durable ledger and never duplicate an accepted job on a slow poll.

Stop on any failed ancestry or earlier-date assertion, ambiguous/conflicting parent mapping, incomplete race, changed row set, unverifiable seed graph/centroid, category mismatch, unavailable dependency, or artifact hash failure. Report and preserve the failure instead of silently altering the experiment. Do not read test rows while addressing a training/validation issue. If a correction changes scientific choices, issue a new versioned protocol and rerun affected arms. The previous 2017-cutoff graphs and assembly outputs are preserved only as superseded exploratory preparation; their 2018–2021 models are not part of this matrix and must not be launched.
